# Holder Distribution — Claude Handoff

## Git rule (owner, standing; rewritten 2026-11-19)

Committing to GitHub is allowed in this repo: create branches, commit, push, open pull requests, merge them when their checks pass, and dispatch workflows. Ask the owner once, at the start of a conversation, which permissions apply to it (local commands such as Bash and PowerShell; GitHub actions), then work inside that grant and do not ask again. Subagents never run state-changing git or gh commands and never hold a grant; the main session does. A request to onboard a coin is itself the grant for everything the onboarding needs (`.claude/skills/onboard-project/SKILL.md`).

**Safety gates (owner, 2026-11-19). A grant does not lift these:**

- **Pull requests.** A change reaches `main` through a pull request whose checks (`verify`, CodeQL) pass. After a merge or a dispatch, check the result (CI on `main`, the run's conclusion) and report a failure with the revert ready.
- **Asked every time, naming the exact action:** a direct push to `main`; a force-push or any rewrite of pushed history; deleting a remote branch that is not merged, a tag or a release; `--no-verify`, `gh pr merge --admin` or merging with failing checks; `reset --hard`, `clean`, removing a worktree or anything else that discards work; git config, repository settings, secrets, rulesets; dispatching a workflow outside the routine list (`ci`, `pipeline-watchdog`, `refresh-holders` for a failed night, `refresh-wallet-flows`, `refresh-ledger`, `refresh-staker-balances`, `test-rpc-keys`, `detect-cex-candidates`, `diagnose-council-transfers`, `onboard-project` for a coin the owner named); deploys. The harness asks on these (`.claude/hooks/git-gate.mjs`, the `ask` list and the classifier text in `.claude/settings.local.json`). Never work around a prompt or a block.
- **Secrets.** The `pre-push` hook scans every pushed commit (`.claude/hooks/prepush-scan.mjs`), and GitHub push protection is on. A keyed RPC URL, a token or a passphrase never goes into a commit, a log or the chat.
- **Record.** Every state-changing git or GitHub command of a Claude session is appended to `tasks/git-audit.jsonl` (time, session, directory, command, decision).
- **Undo.** A bad change is undone with `git revert` through a pull request, never by rewriting history. GitHub refuses a force-push to `main` and its deletion (ruleset "protect main"). Feeds are regenerated by script, never hand-edited.
- **One nightly run per day.** A workflow run for a coin whose scheduled night failed is a recovery and is inside the grant. A second run for a coin that already has that day's data needs the owner's word.

**README rule (owner, standing):** every PR that is pushed must update `README.md` in the same PR: the project list, the layout map, and "Recent work" with the merged PR numbers and what changed. A PR without that update is not ready to push.

## Explorer parity rule (owner, standing, 2026-11-14)

The holder balance must match what blockchain explorers show, for all tokens. This is a repo-wide rule.

Scope (owner, same day): every token lists every address with a positive balance. No minimum-balance floor, and a contract is a holder unless a classification list (exclusions, CEX, DEX) says otherwise. A snapshot that is too large is fixed by its storage layout, never by listing fewer rows or changing a balance.

## What this repo is

A single-page React app that shows on-chain analytics for every registered token (`config/projects.json`): holder distribution, supply breakdown, exchange flows, and historical growth trends. The site is the product; each token is a page at `/<slug>`, and TEL is one of them, not the product. It lives at **holderdistribution.com** and is deployed on Netlify.

The site was originally extracted from a larger Telcoin Hub multi-page app. It is now its own standalone product under the **Holder Distribution** brand — rebranded from "TelcoinHub" to "Holder Distribution".

## Deployment

**Deploys are manual-only.** Git pushes do NOT trigger Netlify builds.

To deploy:
1. Push code to `main` on GitHub
2. Go to the Netlify dashboard → trigger a manual deploy

Why: data refresh commits run frequently and shouldn't trigger full rebuilds.

## Where things live

- `config/projects.json` + `config/projects/<slug>.json`: token registry and per-token config (source of truth). `config/exclusions.json`, `cex-wallets.json`, `chains.json`: shared classification.
- `scripts/*.js`: feed generators and pipeline CLIs. `scripts/lib/`: shared logic with sibling `*.test.js` (rpc, replay, supply, circulating, holders).
- `scripts/check-feed-consistency.js` (`npm run check:feeds`), `pipeline-health.js`: feed gates.
- `scripts/datachecks/`, `src/datachecks/` (`npm run check:data`): checks of the committed data. `npm test` must pass without `public/data/` and `data/`; a test that needs real data belongs in a datacheck file. `scripts/fixtures/`: small inputs for code tests.
- `scripts/lib/stateStore.js`: the only way to read a past version of a data file (git today). No other script or workflow step reads data out of git history (`gitReadGuard.test.js`).
- `public/data/` (TEL legacy root) and `public/data/<slug>/`: generated feeds. Never hand-edit; regenerate by script. `data/`: caches and checkpoints.
- `.github/workflows/`: nightly refresh (`refresh-holders.yml`), backfills, replays.
- `src/lib/`: pure helpers (charts: `chartAxes`, `chartZoom`; supply: `supplyBreakdown`, `chainViews`; staking: `staking*`; `projects.ts` registry reader).
- `src/components/`: widgets; `chart/`, `terminal/`, `tierflow/`, `ui/` subfolders. `src/pages/`: routes.
- `netlify/functions/`: `live-data.mjs` (serves latest feeds from GitHub), `forensics-gate.cjs`. `netlify.toml`: manual-deploy rules.
- Local-only, uncommitted: `tasks/`, `.cursor/`, and `.claude/` except `.claude/skills/`; `scripts/CLAUDE.md` is tracked. `design-system/`, `docs/`: specs.
- Harness: `.claude/HANDOFF.md` (session facts, decisions, progress); `npm run receipt -- --objective "..." [--verify]` writes `tasks/receipt.md` (what changed, what passed); `.claude/agents/verifier.md` (adversarial check before a slice is marked done); `tasks/harness-audit.md` (which gates caught which lessons). Git permissions: routine git and GitHub commands run without a prompt; the gated actions of the Git rule are set to `ask` in `.claude/settings.local.json`, and `.claude/hooks/git-gate.mjs` logs every state-changing command to `tasks/git-audit.jsonl`.
